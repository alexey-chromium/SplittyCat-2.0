# Сценарии использования

## UC-001. Регистрация пользователя

### Актор
- Незарегистрированный пользователь (`НП`)

### Предусловия
- Пользователь не зарегистрирован в системе.

### Основной сценарий
1. Пользователь открывает форму регистрации.
2. Пользователь вводит регистрационные данные.
3. Система валидирует введенные данные.
4. Система создает учетную запись пользователя.
5. Система авторизует пользователя.

### Альтернативы / исключения
- Введены некорректные данные.
- Пользователь с такими данными уже существует.

### Постусловия
- В системе создан зарегистрированный пользователь.
- Пользователь может создавать события и привязываться к слотам.

---

## UC-002. Создание события

### Актор
- Зарегистрированный пользователь (`ЗП`)

### Предусловия
- Пользователь зарегистрирован и авторизован.

### Основной сценарий
1. Пользователь инициирует создание события.
2. Пользователь заполняет данные события.
3. Система валидирует данные события.
4. Система создает событие.
5. Система назначает пользователя создателем события.
6. Система создает слот и привязывает создателя события к нему.
6. Система формирует код приглашения и ссылку-приглашение.

### Альтернативы / исключения
- Введены некорректные данные события.

### Постусловия
- Событие создано.
- Создан слот участника и создатель события привязан к нему.
- Пользователь становится владельцем созданного события.

---

## UC-003. Открытие события по ссылке-приглашению

### Актор
- Любой пользователь (`ЛП`)

### Предусловия
- У пользователя есть ссылка-приглашение.
- Ссылка-приглашение действительна.

### Основной сценарий
1. Пользователь переходит по ссылке-приглашению.
2. Система проверяет действительность ссылки.
3. Система открывает событие.

### Альтернативы / исключения
- Ссылка-приглашение недействительна.

### Постусловия
- Пользователь может просматривать элементы события.

---

## UC-004. Привязка к свободному слоту

### Актор
- Просматривающий (`П`)

### Предусловия
- Пользователь зарегистрирован.
- Пользователь открыл событие по ссылке-приглашению.
- В событии есть подходящий свободный слот.
- Пользователь еще не привязан ни к одному участнику данного события.

### Основной сценарий
1. Пользователь просматривает свободные слоты события.
2. Пользователь выбирает подходящий слот.
3. Система проверяет, что слот свободен.
4. Система привязывает пользователя к выбранному слоту.
5. Пользователь получает роль авторизованного участника события (`АУС`).

### Альтернативы / исключения
- Выбранный слот уже занят.
- Пользователь не зарегистрирован.
- Пользователь уже привязан к участнику данного события.

### Постусловия
- Пользователь привязан к слоту.
- Пользователь становится авторизованным участником события.

---

## UC-005. Создание и занятие своего слота

### Актор
- Просматривающий (`П`)

### Предусловия
- Пользователь зарегистрирован.
- Пользователь открыл событие по ссылке-приглашению.
- Пользователь еще не привязан ни к одному участнику данного события.
- Подходящего свободного слота нет.
- Пользователь еще не создавал новый слот для себя в рамках данного события.

### Основной сценарий
1. Пользователь инициирует создание своего слота.
2. Пользователь вводит данные нового слота.
3. Система валидирует данные.
4. Система создает новый слот.
5. Система сразу привязывает пользователя к созданному слоту.
6. Пользователь получает роль авторизованного участника события (`АУС`).

### Альтернативы / исключения
- Пользователь не зарегистрирован.
- Пользователь уже привязан к участнику данного события.
- Пользователь уже создавал слот для себя в рамках данного события.
- Введены некорректные данные.

### Постусловия
- В событии создан новый слот.
- Пользователь привязан к этому слоту.

---

## UC-006. Отвязка от своего слота

### Актор
- Авторизованный участник события (`АУС`)

### Предусловия
- Пользователь привязан к своему слоту.
- Пользователь не является создателем события.

### Основной сценарий
1. Пользователь инициирует отвязку от своего слота.
2. Система проверяет, что пользователь привязан именно к этому слоту.
3. Система проверяет, что пользователь не является создателем события.
4. Система снимает привязку пользователя со слота.
5. Пользователь теряет роль авторизованного участника события.

### Альтернативы / исключения
- Пользователь является создателем события.
- Пользователь не привязан ни к одному слоту данного события.

### Постусловия
- Слот становится свободным.
- Пользователь возвращается в состояние просматривающего (`П`).

---

## UC-007. Создание свободного слота

### Актор
- Авторизованный участник события (`АУС`)

### Предусловия

### Основной сценарий

2. Пользователь вводит данные слота.
3. Система валидирует данные.
4. Система создает новый свободный слот в событии.

### Альтернативы / исключения
- Введены некорректные данные.

### Постусловия
- В событии создан новый свободный слот.

---

## UC-008. Удаление свободного слота

### Актор
- Авторизованный участник события (`АУС`)

### Предусловия
- Пользователь привязан к слоту в данном событии.
- Удаляемый слот свободен.
- Удаляемый слот не участвует ни в одной доле.

### Основной сценарий
1. Пользователь инициирует удаление свободного слота.
2. Система проверяет, что слот не занят.
3. Система проверяет, что слот не участвует ни в одной доле.
4. Система удаляет слот.

### Альтернативы / исключения
- Слот занят пользователем.
- Слот участвует хотя бы в одной доле.

### Постусловия
- Свободный слот удален из события.

---

## UC-009. Создание траты

### Актор
- Авторизованный участник события (`АУС`)

### Предусловия
- Пользователь привязан к слоту в данном событии.

### Основной сценарий
1. Пользователь инициирует создание траты.
2. Пользователь вводит данные траты
3. Система валидирует данные траты.
4. Система проверяет, что плательщик относится к тому же событию.
5. Система проверяет, что сумма долей равна сумме траты.
6. Система создает трату.
7. Система назначает пользователя создателем траты (`СТ`).

### Альтернативы / исключения
- Введены некорректные данные.
- Плательщик не относится к событию.
- Сумма долей не равна сумме траты.

### Постусловия
- Трата создана в рамках события.
- Сохранены доли участников траты.

---

## UC-010. Удаление траты

### Актор
- Создатель траты (`СТ`)
- Создатель события (`СС`)

### Предусловия
- Трата существует.
- Пользователь имеет право на удаление этой траты.

### Основной сценарий
1. Пользователь инициирует удаление траты.
2. Система проверяет права пользователя.
3. Система удаляет трату.
4. Система удаляет связанные с тратой доли.

### Альтернативы / исключения
- Пользователь не является создателем траты или создателем события.

### Постусловия
- Трата удалена.
- Связанные доли удалены.

---

## UC-011. Просмотр расчета долгов

### Актор
- Авторизованный участник события (`АУС`)

### Предусловия
- Пользователь привязан к слоту в рамках данного события.

### Основной сценарий
1. Пользователь открывает расчет долгов по событию.
2. Система собирает данные по тратам и долям.
3. Система рассчитывает:
    - сколько и кто должен пользователю
    - сколько и кому должен пользователь
4. Система отображает результат расчета.

### Альтернативы / исключения
- В событии нет трат.
- Пользователь не привязан к слоту в рамках события.

### Постусловия
- Пользователь видит актуальный расчет долгов по событию.

---

## UC-012. Замена ссылки-приглашения

### Актор
- Создатель события (`СС`)

### Предусловия
- Пользователь является создателем события.

### Основной сценарий
1. Пользователь инициирует замену ссылки-приглашения.
2. Система генерирует новый код приглашения.
3. Система формирует новую ссылку-приглашение.
4. Система инвалидирует предыдущую ссылку-приглашение.
5. Система сохраняет новую ссылку.

### Альтернативы / исключения
- Пользователь не является создателем события.

### Постусловия
- У события действует новая ссылка-приглашение.
- Предыдущая ссылка недействительна.

---

### Актор

### Основной сценарий
